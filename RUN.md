# Шпаргалка запуска

Команды для локального прогона на dev-машине — в конфигурации, максимально близкой
к продовой. Установка описана в [README](README.md), развёртывание на даче —
в [DEPLOY.md](DEPLOY.md).

Нужны три процесса: LLM, преобразование голоса и сам агент. Первые два — в отдельных
терминалах, они работают, пока нужны.

На dev-машине (RTX 2070, 8 ГБ) видеопамяти под всё сразу **не хватает** — подробности
и расчёт ниже, в разделе «Видеопамять». Поэтому здесь контекст LLM ужат, а RVC вынесен
на процессор. На проде (10 ГБ и монитор на встроенной графике) обе оговорки не нужны.

## 1. LLM (llama-server)

Из корня проекта:

```bash
../llama.cpp/build/bin/llama-server -m models/llm/Qwen3-4B-Q4_K_M.gguf \
    -ngl 99 -c 2048 --cache-type-k q8_0 --cache-type-v q8_0 \
    --host 127.0.0.1 --port 8080
```

Контекста 2048 хватает: в истории диалога максимум 8 коротких реплик.

## 2. Преобразование голоса (RVC) — на CPU

```bash
cd ../Retrieval-based-Voice-Conversion-WebUI
CUDA_VISIBLE_DEVICES= .venv/bin/python infer-http-service.py --port 8081
```

`CUDA_VISIBLE_DEVICES=` прячет видеокарту, и RVC сам переключается на CPU в fp32.
Это не жертва: в конвейере он работает тогда, когда GPU уже отдал ответ LLM. На
9950X3D конвертация занимает 0.6–0.7 с (первая — 2.5 с на прогрев).

## 3. Агент

Дождитесь, пока поднимутся оба сервиса:

```bash
curl -s http://127.0.0.1:8080/health    # {"status":"ok"}
curl -s http://127.0.0.1:8081/health    # {"status":"ok","voice":"voicevox_speaker_43",...}
```

Затем из корня проекта:

```bash
.venv/bin/python main.py run --live --responder llm --rvc \
    --profile prod --threshold 0.00067
```

Скажите «**Феечка**, как слышно?» → пауза около секунды → ответ. Следующие 60 секунд
позывной не нужен, «отбой» закрывает диалог. Остановка — `Ctrl+C`.

## Что стоит знать

- **Наушники, а не колонки** — иначе агент услышит собственный ответ. PTT здесь
  заглушка (`dummy`), в эфир ничего не уходит.
- **Порог `--threshold` свой на каждой установке.** Значение выше снято с микрофона
  dev-машины; своё получите командой
  `main.py calibrate --live --seconds 12`.
- **Если агент стартовал раньше сервисов** — он не падает, а пишет `[warn]`: без
  llama-server молчит, без RVC передаёт голосом Piper.
- **Первый запуск `--profile prod` дольше**: `large-v3` грузится около десяти секунд,
  плюс пара секунд на прогрев при первой фразе.
- Для быстрых итераций, когда проверяете механику, а не качество распознавания, —
  `--profile fast` (модель `small`, грузится за пару секунд).

## Видеопамять

На 2070 (8 ГБ) наивная конфигурация — `-c 4096` и RVC на видеокарте — падает с
`CUDA failed with error out of memory`, причём **не при старте, а на первой
транскрипции**: инициализация проходит, а буферов энкодера Whisper уже не хватает.

Замерено на dev-машине:

| Что | VRAM |
|---|---|
| десктоп: gnome-shell, Telegram, Element, Chrome, терминал | **2.5 ГБ** |
| llama-server, `-c 4096` | 3.1 ГБ |
| llama-server, `-c 2048` + KV `q8_0` | **2.7 ГБ** |
| Whisper `large-v3` int8 в пике | ~2.5 ГБ |
| Whisper `small` int8 | ~0.7 ГБ |
| RVC на GPU (fp16) | ~1.5 ГБ |
| RVC на CPU | **0** |

Итог рабочей конфигурации выше — **5.1 ГБ из 8**, с запасом почти в 3 ГБ.

Главное, что легко упустить: **десктоп занимает 2.5 ГБ**, потому что монитор на
dev-машине подключён к той же 2070. С `--profile fast` проблема не проявляется —
`small` укладывается в остаток, поэтому она и всплывает только при переходе на `prod`.

Если хочется вернуть RVC на видеокарту: закрыть Telegram, Element и Chrome —
это освободит около 450 МБ.

**На проде этого всего не будет:** 10 ГБ видеопамяти, монитор на встроенной Intel HD
2000, так что вся память достаётся моделям — там идут и `-c 4096`, и RVC на GPU.

## Чем это отличается от прода

Три вещи, и все они в [DEPLOY.md](DEPLOY.md):

| | Локально | На проде |
|---|---|---|
| PTT | заглушка | `--ptt txdbreak --port /dev/ttyUSB0` |
| Звуковая карта | системный дефолт | `--device-rate 48000` (Sound Blaster Live! работает на 48 кГц) |
| RVC | на CPU, не хватает VRAM | на GPU, в fp32 — переключается сам по имени карты |
| Контекст LLM | `-c 2048` + KV `q8_0` | `-c 4096`, памяти хватает |

То есть боевая команда выглядит так:

```bash
.venv/bin/python main.py run --live --responder llm --rvc \
    --profile prod --device-rate 48000 --threshold ПОРОГ \
    --ptt txdbreak --port /dev/ttyUSB0
```

На проде всё это поднимается systemd-юнитами, вручную запускать не придётся —
см. раздел «Автозапуск» в DEPLOY.md.

## Замер локальной конфигурации

Синтетический эфир (три передачи, полоса 300–3400 Гц), `--profile prod --rvc`,
RVC на CPU — для сверки, если что-то станет заметно медленнее:

```
  #   приём   STT     LLM     TTS    итого   эфир  ответ
  1    2.68    0.48    0.18    0.88    1.55    1.42   да
  2    1.76    0.35    0.15    1.04    1.53    2.30   да
  3    3.22    0.47    0.14    0.93    1.54    1.91   да
  бюджет 10 с — укладываемся (худшая фраза 1.55 с)
```

В колонке TTS здесь Piper вместе с RVC на процессоре. Когда RVC вернётся на
видеокарту, она уйдёт обратно к ~0.3 с.
